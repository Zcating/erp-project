# 认证：单一管理员账号 + session cookie，不做角色与权限

参考应用加一个最简登录：预置一个管理员账号，登录成功后下发 session cookie，业务接口一律要求登录态。理由：有了前端界面就需要一个「未登录不能操作」的边界，否则任何能访问服务的人都能改库存；角色与权限模型对单组织参考应用是过度设计，业务方接入时可自行替换。

## Consequences

- Fastify 是会话的签发与校验权威：登录校验、会话存储、过期判定都在它这边。
- 前端只做登录表单与会话状态的读取，不自己签发 token、不存密码、不在浏览器里保存会话标识。
- 浏览器侧的会话 cookie 由 web 的 server function 在登录成功时种下（web 同源），后续请求由 server function 透传给 Fastify 校验；不引入第二套会话系统。
- 未登录访问业务接口返回 401；前端据此跳转登录页。
- 不做 RBAC、不做多用户、不做密码找回；管理员账号通过环境变量或种子数据提供。
