# 单据采用「草稿 → 已过账 → 已作废」状态机，只有过账才动库存

所有业务单据都有状态：`草稿` → `已过账` → `已作废`。草稿可改可删；过账才产生库存与成本影响；已过账单据不可修改，只能作废，作废时产生反向流水冲销其影响。理由：进销存系统里「录单」与「入账」必须分开，否则草稿数据会污染库存与成本流水；反过来，做完的单据不能直接编辑，必须留作废痕迹，这是审计与对账的前提。

## Consequences

- 「过账」是内核里唯一改变库存的动作，所有库存变化都来自某张单据的过账或作废。
- 过账必须在单个数据库事务内完成（锁库存行 → 校验不变量 → 写库存 → 写流水 → 改单据状态）。
- 作废走「反向单据/红冲」语义，不做物理删除；库存流水因此是追加写的账本。
- 参考应用的 HTTP 接口要把「过账」暴露为独立动作（如 `POST /purchase-inbounds/{id}/post`），不与创建混在一起。
