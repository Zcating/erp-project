# 数值精度与舍入规则写死在规格里

数量、单价、金额一律用**十进制定点数**，精度固定为：数量 `numeric(18,3)`、单价 `numeric(18,6)`、金额 `numeric(18,2)`；成本单价与加权平均成本按 `numeric(18,6)` 计算。所有舍入**显式使用四舍五入（half-up）**。

理由：JavaScript 的 `round()` 是银行家舍入（half-even），运行时默认行为会制造金额尾差；数据库 `DECIMAL` 的默认舍入也不该被当成业务契约。金额尾差一旦入库就难以追溯，所以精度与舍入规则必须在规格里定死，而不是依赖语言或数据库的默认值。

## Consequences

- 内核禁止使用二进制浮点（`number`）承载金额与数量计算；用 decimal 库（如 `decimal.js`）或以最小单位整数运算，并在端口边界转换。
- 单价精度必须 ≥ 金额精度（6 ≥ 2），否则加权成本会失真。
- 金额 = 数量 × 单价，舍入到金额精度；成本结转金额同理。舍入规则在规格与测试中各写一次，不允许散落。
- 允许按商品配置更细的精度是可选项，但本版本不做（见 ADR-0006 的范围决定）。
